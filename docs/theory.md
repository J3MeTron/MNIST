# Математика проекта: все выводы в одном месте

Шпаргалка по формулам, которые разобраны в ноутбуках. Здесь только математика,
без кода и без объяснений "зачем" - за ними в ноутбуки.

Обозначения:

| Символ | Форма | Что это |
|---|---|---|
| `B` | - | размер мини-батча |
| `D` | - | число признаков, для MNIST 784 |
| `H` | - | размер скрытого слоя, у нас 128 |
| `C` | - | число классов, 10 |
| $X$ | (B, D) | батч картинок, значения в [0, 1] |
| $y$ | (B,) | int64, правильные метки классов |
| $Y$ | (B, C) | one-hot кодирование $y$ |
| $Z$ | (B, C) | логиты |
| $P$ | (B, C) | $P = \mathrm{softmax}(Z)$ |
| $G$ | (B, C) | $G = \partial L / \partial Z$ |

---

## 1. Прямой проход

### Линейный слой

$$Z = X W + b, \qquad W \in \mathbb{R}^{D \times C},\ b \in \mathbb{R}^{C}$$

Поэлементно: $Z_{n,k} = \sum_{i=1}^{D} X_{n,i} W_{i,k} + b_k$.

Смещение $b$ формы (C,) складывается с матрицей (B, C) через broadcasting:
оно повторяется для каждой строки батча.

### Softmax

$$P_k = \frac{e^{Z_k}}{\sum_{j=1}^{C} e^{Z_j}}$$

Свойства: $P_k > 0$, $\sum_k P_k = 1$, монотонность по $Z_k$ (порядок классов
не меняется, поэтому `argmax` по логитам и по вероятностям совпадают).

**Инвариантность к сдвигу.** Для любого числа $m$:

$$\frac{e^{Z_k - m}}{\sum_j e^{Z_j - m}} = \frac{e^{-m} e^{Z_k}}{e^{-m} \sum_j e^{Z_j}} = \frac{e^{Z_k}}{\sum_j e^{Z_j}}$$

Берут $m = \max_j Z_j$: тогда наибольший показатель равен $e^0 = 1$ и
переполнения не бывает. В `float32` уже $e^{89}$ дает `inf`, так что это
не теоретическая тонкость.

### log_softmax

$$\log P_k = Z_k - \log \sum_j e^{Z_j} = (Z_k - m) - \log \sum_j e^{Z_j - m}$$

Считать как `softmax(z).log()` нельзя: при малом $P_k$ получается
`log(0) = -inf`. В устойчивой форме логарифм берется от суммы, которая
не меньше 1 (слагаемое с $j = \arg\max$ дает ровно 1).

### ReLU

$$\mathrm{ReLU}(z) = \max(0, z)$$

### Перекрестная энтропия

$$L = -\frac{1}{B} \sum_{n=1}^{B} \log P_{n, y_n}$$

Среднее, а не сумма: тогда масштаб ошибки и градиента не зависит от `B`,
и шаг `lr` не надо подбирать заново при смене размера батча.

---

## 2. Градиент по логитам: главная формула

$$\boxed{\ G = \frac{\partial L}{\partial Z} = \frac{\mathrm{softmax}(Z) - Y}{B}\ }$$

### Вывод

Для одного примера с правильным классом $y$:

$$L_n = -\log P_y = -Z_y + \log \sum_j e^{Z_j}$$

Дифференцируем по произвольному $Z_k$. Первое слагаемое:

$$\frac{\partial(-Z_y)}{\partial Z_k} = -[k = y]$$

Второе слагаемое:

$$\frac{\partial}{\partial Z_k} \log \sum_j e^{Z_j} = \frac{1}{\sum_j e^{Z_j}} \cdot e^{Z_k} = P_k$$

Складываем:

$$\frac{\partial L_n}{\partial Z_k} = P_k - [k = y]$$

По всему батчу в матричном виде это $P - Y$, деление на $B$ приходит из
среднего в определении $L$.

### Смысл

Градиент по логиту - "насколько предсказание превысило правду":

* для правильного класса $P_y - 1 < 0$, логит надо поднять;
* для остальных $P_k - 0 > 0$, логиты надо опустить;
* сумма элементов каждой строки $G$ равна нулю, потому что $\sum_k P_k = 1$.

Простота формулы - следствие того, что softmax и логарифм взаимно
упрощаются. Поэтому в библиотеках их реализуют одной операцией
(`CrossEntropyLoss` принимает логиты, а не вероятности).

---

## 3. Градиент через линейный слой

Пусть $Z = X W + b$ и известен $G = \partial L / \partial Z$ формы (B, C).

### По весам

Вес $W_{i,k}$ входит в $Z_{n,k}$ для **каждого** $n$, причем
$\partial Z_{n,k} / \partial W_{i,k} = X_{n,i}$. Вклады всех примеров
складываются:

$$\frac{\partial L}{\partial W_{i,k}} = \sum_{n} G_{n,k} X_{n,i} \quad \Longrightarrow \quad \boxed{\ \frac{\partial L}{\partial W} = X^\top G\ }$$

Формы: $(D, B) \times (B, C) = (D, C)$ - совпадает с формой $W$.

### По смещениям

$b_k$ входит в $Z_{n,k}$ с коэффициентом 1:

$$\frac{\partial L}{\partial b_k} = \sum_n G_{n,k} \quad \Longrightarrow \quad \boxed{\ \frac{\partial L}{\partial b} = \mathrm{sum}(G, \text{ось } 0)\ }$$

Форма: $(C,)$.

### По входу

Нужен, чтобы передать градиент предыдущему слою:

$$\frac{\partial L}{\partial X_{n,i}} = \sum_k G_{n,k} W_{i,k} \quad \Longrightarrow \quad \boxed{\ \frac{\partial L}{\partial X} = G W^\top\ }$$

Формы: $(B, C) \times (C, D) = (B, D)$.

### Контроль по формам

Порядок множителей можно не выводить, а восстановить. Нужна матрица формы
$W$, то есть $(D, C)$; есть $X$ формы $(B, D)$ и $G$ формы $(B, C)$;
собрать $(D, C)$ можно единственным способом - `X.T @ G`. Эта проверка
ловит почти все опечатки в обратном проходе.

---

## 4. Градиент через ReLU

Производная ReLU **поэлементная**: выход $H_{n,j}$ зависит только от входа
$Z_{n,j}$. Поэтому цепное правило здесь - поэлементное умножение, а не
матричное:

$$\boxed{\ \frac{\partial L}{\partial Z} = \frac{\partial L}{\partial H} \odot [Z > 0]\ }$$

$$\mathrm{ReLU}'(z) = \begin{cases} 1, & z > 0 \\ 0, & z < 0 \end{cases}$$

В точке $z = 0$ производной формально нет (слева 0, справа 1);
договоренность - считать нулем. На `float32` попадание ровно в нуль
практически невероятно.

**Следствие: мертвые нейроны.** Через закрытый нейрон градиент не проходит
вообще. Если нейрон ушел в отрицательную зону на всех примерах, его веса
перестают обновляться и он уже не оживет.

---

## 5. Полный обратный проход MLP

Сеть: $X \to W_1, b_1 \to Z_1 \to \mathrm{ReLU} \to H_1 \to W_2, b_2 \to Z_2 \to L$

| № | Формула | Форма |
|---|---|---|
| 1 | $G_2 = (\mathrm{softmax}(Z_2) - Y) / B$ | (B, C) |
| 2 | $\partial L/\partial W_2 = H_1^\top G_2$ | (H, C) |
| 3 | $\partial L/\partial b_2 = \mathrm{sum}(G_2, 0)$ | (C,) |
| 4 | $\partial L/\partial H_1 = G_2 W_2^\top$ | (B, H) |
| 5 | $G_1 = (\partial L/\partial H_1) \odot [Z_1 > 0]$ | (B, H) |
| 6 | $\partial L/\partial W_1 = X^\top G_1$ | (D, H) |
| 7 | $\partial L/\partial b_1 = \mathrm{sum}(G_1, 0)$ | (H,) |

Новая по сравнению с линейной моделью здесь только строка 5. Строки 2-4 и
6-7 - это одна и та же операция "градиент через линейный слой", вызванная
дважды с разными входами ($H_1$ для второго слоя, $X$ для первого).

Именно поэтому библиотеки устроены как набор слоев: раз каждый слой умеет
принять градиент по своему выходу и отдать градиент по своему входу, слои
складываются в любую цепочку, и обратный проход собирается автоматически.
Это и делает autograd.

---

## 6. Шаг градиентного спуска

$$p \leftarrow p - \eta \frac{\partial L}{\partial p}$$

Минус потому, что градиент указывает направление наибольшего **роста**
ошибки.

С momentum (то, что добавляет `optim.SGD(momentum=...)`):

$$v \leftarrow \mu v + g, \qquad p \leftarrow p - \eta v$$

Шум по батчам усредняется, систематическое направление усиливается
примерно в $1/(1 - \mu)$ раз.

---

## 7. Инициализация

$$W \sim \frac{\mathcal{N}(0, 1)}{\sqrt{n_{in}}}, \qquad b = 0$$

**Обоснование.** Логит - сумма $n_{in}$ слагаемых. Для независимых
слагаемых дисперсия суммы равна сумме дисперсий, то есть растет как
$n_{in}$, а стандартное отклонение - как $\sqrt{n_{in}}$. Без
масштабирования логиты получились бы с разбросом $\sqrt{784} \approx 28$;
softmax от таких логитов выдает почти 0 и почти 1, градиент $P - Y$
становится почти нулевым, и обучение встает.

`nn.Linear` по умолчанию использует равномерное распределение на
$[-1/\sqrt{n_{in}},\ 1/\sqrt{n_{in}}]$. Распределение другое, **масштаб
тот же**.

---

## 8. Приемы проверки

### Прикидка стартовой ошибки

Необученная модель дает каждому классу вероятность $1/C$, значит

$$L_{\text{старт}} \approx -\log \frac{1}{C} = \log C$$

Для 10 классов это $\approx 2.303$. Если на старте ошибка не около 2.3 -
проблема в инициализации или в нормировке данных, и запускать обучение
бессмысленно.

### Численная проверка градиента

$$\frac{\partial L}{\partial W_{i,k}} \approx \frac{L(W + h E_{ik}) - L(W - h E_{ik})}{2h}$$

Центральная схема: погрешность $O(h^2)$ против $O(h)$ у односторонней.

Две обязательные оговорки:

1. **Считать в `float64`.** Числитель - разность почти равных чисел; в
   `float32` (7 значащих цифр) от нее остается две-три цифры, и отличить
   ошибку в формуле от ошибки округления невозможно. В `float64` с
   $h = 10^{-6}$ сходимость до 7-8 знаков.
2. **Проверять там, где градиент не нулевой.** У MNIST пиксели по краю
   нулевые во всех примерах батча, и градиент по их весам равен **ровно**
   нулю при любой, даже неверной формуле. Такая проверка ничего не
   проверяет.

### Тройная сверка

Аналитическая формула, конечные разности и autograd - три независимых
источника. Сошлись все три - ошибка исключена. Критерий `allclose`, а не
`==`: сложение `float32` неассоциативно, расхождение порядка $10^{-7}$
нормально.

## 9. Почему линейная модель упирается в 92%

Линейная модель держит **один** шаблон на класс (столбец $W[:, k]$,
который можно посмотреть как картинку 28x28) и считает похожесть на него
скалярным произведением. Граница между любыми двумя классами у нее -
гиперплоскость.

Но "7" бывает с перекладиной и без, "1" вертикальной и наклонной, "4"
замкнутой и открытой. Усреднение по вариантам дает размытое пятно, плохо
похожее на каждый из них. Это ограничение модели, а не нехватка данных
или шагов обучения.

Скрытый слой снимает ограничение: первый слой строит $H$ промежуточных
признаков (штрихи, изгибы, замкнутые области), второй линейно комбинирует
их. Без нелинейности между слоями это не работало бы:

$$(X W_1 + b_1) W_2 + b_2 = X (W_1 W_2) + (b_1 W_2 + b_2)$$

Произведение матриц - снова матрица, то есть два линейных слоя подряд
эквивалентны одному. ReLU - то, что делает сеть нелинейной.
